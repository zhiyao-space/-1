# Requirements Document — 一起玩游戏中心（跑团 + 海龟汤）

Feature Name: game-center
Created: 2026-10-06
Status: approved（用户已确认方向：聊天流内嵌游戏卡，先做跑团+海龟汤，引擎可扩展后续游戏）

## Introduction

在聊天中与角色进行高自由度文字游戏。v1 提供两种玩法：文字跑团（角色当 DM 或队友，自由行动、骰子判定、状态成长、多结局）与海龟汤（情境猜谜，自由提问，是/否/无关判定）。游戏过程以「游戏卡」消息内嵌在聊天流中，游戏叙述以普通消息呈现，用户可随时插嘴聊天再回到游戏。引擎设计为模板化，后续密室逃脱/故事接龙/平行世界等玩法通过新增模板接入。

## Glossary

- **游戏会话（GameSession）**: 一次游戏实例，绑定一个角色与一个聊天会话，独立持久化于 games store。
- **游戏卡（game-card）**: 聊天流中的消息类型，实时渲染游戏会话的状态面板。
- **回合（Turn）**: 玩家一次自由输入引发的一次游戏推进（LLM 判定 + 叙述输出）。
- **判定（Dice）**: 跑团中一次行动的成败判定，骰子由本地随机，目标值与成败解释由 LLM 给出。
- **汤面（Puzzle）**: 海龟汤谜题的表面故事；**汤底（Truth）**: 真相。
- **降级模式**: 用户未配置可用 API 时，由本地文案池与本地骰子逻辑驱动游戏。

## Requirements

### R1 游戏入口

**User Story:** AS 玩家, I want 在聊天输入区的加号面板里选择「一起玩」, so that 我可以随时和当前角色开始一场游戏。

#### Acceptance Criteria

1. WHEN 玩家点击聊天输入区加号面板中的「一起玩」，系统 SHALL 弹出游戏创建面板。
2. WHEN 玩家进入线下叙事模式，加号面板 SHALL 隐藏「一起玩」入口（与图片/语音/转账等富媒体一致的可见性规则）。

### R2 游戏创建

**User Story:** AS 玩家, I want 选择游戏类型并自定义开场设定, so that 每局游戏都符合我当下的心情。

#### Acceptance Criteria

1. WHEN 玩家在创建面板选择「文字跑团」，系统 SHALL 提供至少 5 个预设世界模板（末世/修仙/校园/克苏鲁/西幻）并允许玩家自由改写世界观与自身身份。
2. WHEN 玩家在创建面板选择「海龟汤」，系统 SHALL 提供难度选择（简单/普通/烧脑）与主题偏好输入。
3. WHEN 玩家确认创建，系统 SHALL 生成一个游戏会话、在聊天流中插入一条系统消息与一条游戏卡消息，并由角色发出开场叙述。
4. IF 同一聊天会话已存在进行中的游戏，系统 SHALL 提示玩家该游戏正在进行，玩家可选择继续、放弃旧局重开新局。
5. WHEN 玩家未配置可用 API preset，系统 SHALL 以降级模式创建游戏并在系统消息中说明。

### R3 文字跑团玩法

**User Story:** AS 玩家, I want 用任意自由文字描述我的行动, so that 我可以用无限种方式推进冒险。

#### Acceptance Criteria

1. WHILE 一局跑团处于进行中，系统 SHALL 把玩家的普通文本输入路由为游戏回合输入。
2. WHEN 玩家提交一次行动，系统 SHALL 本地掷 1d20 骰子，并由 LLM 结合骰点给出成败判定与叙述。
3. WHEN 一次回合完成，游戏卡 SHALL 更新显示当前场景、生命值、持有物、冒险进度（0-100）。
4. WHILE 冒险进度达到 100，系统 SHALL 输出结局叙述并将游戏置为已结束。
5. IF 玩家生命值归零，系统 SHALL 输出失败结局并将游戏置为已结束。
6. WHEN 玩家使用 OOC 前缀发送消息，系统 SHALL 将该消息按普通聊天处理并让角色跳出游戏视角回应。

### R4 海龟汤玩法

**User Story:** AS 玩家, I want 通过自由提问逼近真相, so that 我和角色能进行一场推理博弈。

#### Acceptance Criteria

1. WHEN 一局海龟汤开始，角色 SHALL 发出汤面叙述，汤底对玩家保密（仅在游戏会话状态中存储）。
2. WHILE 一局海龟汤处于进行中，系统 SHALL 把玩家的普通文本输入路由为提问或猜测。
3. WHEN 玩家提交一次提问，系统 SHALL 由 LLM 判定为「是 / 否 / 无关 / 接近真相」之一并在叙述中解释。
4. WHEN 玩家提出还原真相的完整猜测，系统 SHALL 由 LLM 判定猜中与否；猜中时公布汤底并将游戏置为已结束。
5. WHEN 游戏卡被查看，系统 SHALL 显示已提问列表与每次判定的标记，提供「要提示」按钮（每局限 3 次）。

### R5 聊天流内嵌与插嘴聊天

**User Story:** AS 玩家, I want 游戏发生在聊天流里且随时能插嘴聊别的, so that 游戏与日常聊天无缝融合。

#### Acceptance Criteria

1. WHEN 游戏进行中，聊天流 SHALL 在游戏卡下方持续追加角色叙述消息与玩家行动消息，与普通消息混排。
2. WHEN 游戏进行中且玩家点击输入区的「暂停游戏」胶囊，系统 SHALL 恢复普通聊天路由并允许后续恢复游戏。
3. WHEN 玩家点击已暂停游戏的游戏卡上的「继续」，系统 SHALL 恢复游戏路由并由角色续写场景。
4. WHEN 游戏已结束，游戏卡 SHALL 保持为只读总结面板（结局、用时回合数、关键事件）。

### R6 无 API 降级

**User Story:** AS 玩家, I want 没有 API 配置时也能玩, so that 功能在任何环境下可体验。

#### Acceptance Criteria

1. WHEN 降级模式的跑团进行一次回合，系统 SHALL 用本地骰子与本地事件文案池生成结果叙述。
2. WHEN 降级模式的海龟汤开始，系统 SHALL 从本地谜题池（至少 6 题）抽取汤面与汤底，并用关键词匹配规则给出是/否/无关判定。
3. WHEN 降级模式中玩家猜中汤底关键词或跑团进度达 100，系统 SHALL 按正常规则结束游戏。

### R7 会话管理与存档

**User Story:** AS 玩家, I want 管理我的游戏记录, so that 我可以回顾或删除过往对局。

#### Acceptance Criteria

1. WHILE 存在任意游戏，系统 SHALL 在游戏卡面板提供「结束并归档」操作，归档后游戏卡折叠为摘要。
2. WHEN 玩家在归档卡上选择删除，系统 SHALL 从聊天流移除游戏卡并删除对应游戏会话数据。
3. WHEN 应用重启，进行中或已归档的游戏 SHALL 依据持久化数据完整恢复。

### R8 角色一致性

**User Story:** AS 玩家, I want 游戏由当前角色的人格来主持, so that 游戏体验与该角色的性格一致。

#### Acceptance Criteria

1. WHEN 生成游戏叙述，系统 SHALL 将角色人设（buildCharacterPrompt 产出）注入游戏系统提示词。
2. WHEN 角色主持海龟汤出题，系统 SHALL 允许 LLM 结合角色性格调整汤面叙述风格，汤底逻辑保持完整可推理。
